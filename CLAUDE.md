# ~/sa — робоче місце байера

Один репозиторій, три частини й тека заливів поруч:

```
setup.sh                   одна команда встановлення й оновлення: Node, ffmpeg, subs
creative-factory-search/   редактор креативів, сервер, CLI `sa` — код і його README
playbook/                  правила байера: rules.md (вижимка) і compliance/ (правила провайдера)
subs/                      автосубтитри: вотчер над inbox/, стилі, пайплайн; таба в редакторі кличе його ж
launches/                  заливи байера (поза git; шлях — `launches_root` у ~/.config/sa/config.json)
```

## Куди йти за чим

- **Новий байер, установка, токени** — `ONBOARDING.md`; «встанови все
  необхідне» — скіл `setup`.
- **Як заливати: зв'язка, біди, стоп, скейл, обсяг** — `playbook/rules.md`,
  дві тисячі слів, читається цілком перед обговоренням матриці. Кожне
  правило несе позначку надійності — називай її байеру.
- **Чи пройде формулювання модерацію** — `playbook/compliance/rules-index.md`
  і правила `CMP-*` поруч; вердикт завжди з id правила, вигаданих id не буває.
- **Як влаштований код, його правила і як його запускати** —
  `creative-factory-search/README.md`, розділ «Shape of the code».
- **Субтитри** — `subs/README.md`; технічні граблі — `subs/technical/README.md`.
- **Що будуємо і чому** — `creative-factory-search/.scratch/prd-autolaunch.md`,
  тікети поруч у `.scratch/autolaunch/issues/`.
- **Скіли** — `.claude/skills/`: `setup` (`setup.sh`, токени, перевірка), `matrix` (обговорити матрицю → `sa expand`),
  `compliance` (вердикт з id `CMP-*` по плейбуку), `launch` (від теки до
  `sa plan`; `--confirm` лишається байеру). Написані під плейбук, у волт не ходять.

## Як іде залив

1. Байер і Claude обговорюють матрицю: топік, ключі, статті, гео, кабінети —
   по `playbook/rules.md`. Матриця — разовий генератор, файлу в неї немає.
2. Тека топіка: `sa new <key>` (новий) або `sa adopt <topic-id> --key <key>`
   (топік уже створений руками на платформі). У `topic.yaml` кожен кабінет
   несе `source: tiktok|facebook`; джерело кампанії — джерело її кабінету.
3. Папки з матриці: `echo '{...}' | sa expand <key>` створює термгрупи, статті
   й кампанії, яких ще немає; одну кампанію додає `sa new campaign <key>
   --termgroup … --article … --language … --country … --account …`. Імена
   папок складає `sa`. Форма JSON — у README редактора, розділ про `sa`.
4. Вміст пишеться файлами: `termgroups/<tg>/keywords.txt`,
   `articles/<a>/article.md`, `campaigns/<c>/script.md`. Статтю і скрипт —
   через комплаєнс до заливу.
5. Креативи: редактор кладе mp4 у `campaigns/<c>/creatives/` кожної кампанії
   мови, а ісходники — у `sources/<дата-час>/`; дизайнер кладе відео в ті
   самі теки кампаній. Однаковий файл у кількох кампаніях `plan` вантажить
   один раз.
6. `sa plan <key>` — що станеться; `sa apply <key> --confirm` — людина.

## Правила

- Мова спілкування — українська; код, коміти й імена файлів — англійською.
- Заливи живуть у `launches/<launch-key>/`; структуру теки задає PRD і
  створюють `sa new`, `sa adopt`, `sa expand`, `sa new campaign`. Не створюй
  тек і yaml руками — виклич команду; руками пишуться лише ключі, статті й
  скрипти.
- `sa plan <key>` можна ганяти скільки завгодно: він читає теку й платформу і
  нічого не створює. `sa apply` створює сутності за живі гроші. Ніколи не
  запускай його сам — тільки людина, після `sa plan`, з `--confirm`;
  `.claude/settings.json` цього репозиторію забороняє команду Claude.
- Волта в цьому репозиторії більше немає: не шукай `sa-knowledge/`, не
  вигадуй нотаток. Що не сказано в плейбуку — так і скажи байеру.
