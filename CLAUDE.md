# ~/sa — робоче місце байера

Один репозиторій, три частини й тека заливів поруч:

```
creative-factory-search/   редактор креативів, сервер, CLI `sa` — код і його README
sa-knowledge/              волт: база знань команди, читається, не редагується
subs/                      автосубтитри: вотчер над inbox/, стилі, пайплайн
launches/                  заливи байера (поза git; шлях — `launches_root` у ~/.config/sa/config.json)
```

## Куди йти за чим

- **Питання по знаннях, зв'язках, комплаєнсу, термінах** — це волт. Відкрий
  `sa-knowledge/CLAUDE.md` і йди строго його кроками: один вхід, дві-три
  нотатки, без `grep` по всій базі. Тут ці правила не дублюються.
- **Як влаштований код і як його запускати** — `creative-factory-search/README.md`.
  Правило репозиторію: `core` — єдиний тестований шов, чисті функції, без
  DOM і мережі.
- **Субтитри** — `subs/README.md`; технічні граблі — `subs/technical/README.md`.
- **Що будуємо і чому** — `creative-factory-search/.scratch/prd-autolaunch.md`,
  тікети поруч у `.scratch/autolaunch/issues/`.

## Правила

- Мова спілкування — українська; код, коміти й імена файлів — англійською.
- Заливи живуть у `launches/<launch-key>/`; структуру теки задає PRD і створює
  `sa new`. Не створюй її руками.
- `sa apply` створює кампанії за живі гроші. Ніколи не запускай його сам —
  тільки людина, після `sa plan`.
- Волт read-only: помітив помилку в нотатці — скажи, не правь.
