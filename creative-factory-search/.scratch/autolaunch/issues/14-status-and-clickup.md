# 14 — Тікет із теки: тека → тікет у ClickUp, залив → in progress

**What to build:** байер не мусить кликати `sa new`, щоб тікет з'явився. Тека з `topic.yaml` у `launches_root` — створена руками у Finder, скопійована від колеги чи зроблена `sa new` — сама дає тікет у листі ClickUp з launch key у назві й полями `topic`, `vertical`, `geo`. Сервер звіряє теки з листом раз на десять хвилин, при старті й після кожного `apply`: тека без `ticket` у `state.json` → тікет шукається в листі за назвою (read-back, щоб загублений `state.json` не дав двійника), не знайшовся → створюється; id і url пишуться в `state.json` як `ticket`. `sa new` іде тим самим шляхом, а не своїм. Коли `apply` зібрав першу кампанію теки (`builder.create` пройшов), тікет переводиться в `in progress`. Правило «стан теки → статус тікета» — чиста функція в `core`: без builder — `to do`, є хоч один builder — `in progress`; `complete` ставить людина, і код його не чіпає й не повертає назад. Назви статусів беруться з листа за іменем; дефолти `to do` / `in progress` перевизначаються в конфігурації. `topic.yaml` отримує необов'язкове поле `geo` (список кодів), яке `sa new --geo` записує туди ж, звідки тікет його читає. Реджекти, `creatives/rejected/`, коментарі про креативи, `launchd` — не в цьому тікеті, підуть окремим.
