# Reporting API (Digifor / Roots) — конфіг для analyze-launch

**Статус: налаштовано, перевірено живими викликами 2026-08-11.**

- **Система:** Roots platform (адмінка — https://admin.digifor.io/analytics)
- **База API:** `https://admin-api.digifor.io/api/reporting/v1`
- **Автентифікація:** `Authorization: Bearer <токен>` + `Accept: application/json`.
  Токен лежить у файлі **`secret/api-key-roots`** (тека в `.gitignore`, у
  репозиторій не потрапляє). У команду підставляй так, щоб не друкувати:
  `TOKEN=$(tr -d '[:space:]' < secret/api-key-roots)`.
- **Скоуп токена: вся організація** (Salyut Partners) — API віддає кампанії
  всіх байерів. Розріз «байер бачить своє» робиться на нашому боці по
  маркеру байера в неймінгу (див. нижче). Байеру чужі цифри не показуй —
  фільтруй перед видачею. (Майбутній скіл для керівника — ті самі виклики
  без фільтра по маркеру.)

## Ендпоінти

Обидва — `GET`, обидва приймають лише два робочі параметри:
`date_type` = `today` | `yesterday` | `last7days` | `MM/dd/yyyy-MM/dd/yyyy`
(слеші в URL кодуй як `%2F`) і `topic_id` (серверний фільтр, працює на обох;
недокументований, але перевірений). Решта параметрів (`campaign_id`,
`status`, `country`, `traffic_source`…) **ігноруються мовчки** — фільтруй
через `jq`.

### 1. `/campaigns` — зріз по кампаніях (спенд, ROI, сетап)

Один рядок = одна кампанія, **агрегат за весь запитаний період, поля дати в
рядках нема**. Динаміка по днях = цикл по днях, один виклик на день
(`date_type=08%2F09%2F2026-08%2F09%2F2026`).

Поля рядка: `campaign_id`, `campaign_name`, `status` (ACTIVE/PAUSED),
`traffic_source`, `topic_id/topic_name/topic_internal_name`, `country`,
`bid`, `bid_strategy`, `budget`, `language`, `theme` (макет лендінга),
`term_group` (група ключів), `cpc`, `revenue`, `clicks` (пошукові),
`s_clicks`, `rpc`, `rps`, `spend`, `profit`, `roi`, `t_cpa`, `s_cpa`,
`g_pctr`, `g_ctr`. Плюс `summary` за період: revenue/spend/profit/clicks
по організації.

### 2. `/revenue` — ревеню по годинах (виплата, дроп дня)

Один рядок = кампанія × година: `date`, `hour`, `topic_*`, `campaign_*`,
`revenue`, `clicks`, `rpc`. **Спенду тут нема.** Діапазон дат віддає всі дні
з датою в рядку — для «ревеню по днях» достатньо одного виклику.

Коди відповідей: 200; 403 — невалідний токен; 404; 500.

## Неймінг кампаній — головний ключ розбору

```
34-<topic_internal_name>-<term_group>-<сорс>-<гео>-<маркер байера>-<MMDD запуску>-GE<номер>
приклад: 34-VadimAvtoFR1-tg_avto_ded_FR-tk-fr-bv-0810-GE02
```

`term_group` може містити дефіси — сегменти зв'язки бери **з кінця**:
`[-1]` номер у пачці, `[-2]` дата запуску MMDD, `[-3]` маркер байера,
`[-4]` гео, `[-5]` сорс (`tk` = TikTok).

- **Зв'язка ↔ topic.** `topic_id` — серверний фільтр, ним звужуй обидва
  ендпоінти. topic_id зв'язки знайди по імені/гео в зрізі `/campaigns`.
- **Залив (запуск) = кампанії одного topic з однаковим MMDD.** «Скільки з
  10 відпрацювало» рахується по такій пачці.
- **Байер = маркер `[-3]`** (станом на 2026-08-11 у видачі: `bv`, `ba`, `v`).
  Маркер байера спитай один раз на початку розмови, якщо ще не знаєш.

## Рецепти

```bash
TOKEN=$(tr -d '[:space:]' < secret/api-key-roots)
B="https://admin-api.digifor.io/api/reporting/v1"
AUTH=(-H "Accept: application/json" -H "Authorization: Bearer $TOKEN")

# 1. Знайти зв'язку байера: кампанії за період, тільки його маркер
curl -s "$B/campaigns?date_type=last7days" "${AUTH[@]}" |
  jq '[.data[] | select((.campaign_name | split("-")[-3]) == "bv")]'

# 2. Зріз заливу: topic + день (цикл по днях від дати запуску)
curl -s "$B/campaigns?date_type=08%2F09%2F2026-08%2F09%2F2026&topic_id=92328" "${AUTH[@]}"

# 3. Ревеню по днях/годинах зв'язки (дроп виплати) — один виклик
curl -s "$B/revenue?date_type=08%2F04%2F2026-08%2F10%2F2026&topic_id=92328" "${AUTH[@]}"
```

## Що API дає для менторських лінз

| Лінза скіла | Звідки |
|---|---|
| скільки з 10 відпрацювало | `/campaigns` по пачці (topic + MMDD): частка з `profit > 0` |
| спенд іде / мікроспенд | `spend` по кампаніях; стоп на $1–2 видно одразу |
| ROI по днях, не кумулятивно | `/campaigns` циклом по днях |
| просадка дня = дроп виплати | `/revenue`: `rpc` по днях — впав RPC при тих самих кліках → виплата |
| бід-сітка чи один бід | `bid` по кампаніях пачки: однаковий всюди → один аукціон |
| чи заливався щодня | MMDD у назвах кампаній байера — пропуски дат видно |
| бюджет душить | `budget` проти `spend` |
| куди розносити | `term_group` × `theme` × `country` — що ще не покрито |

## Чого API не знає — питай байера

Бан/стан кабінета, домен (вік, чи платив), креативи всередині кампанії
(вигорання, канібалізація на рівні варіацій), причина паузи. `country` в
кампаніях часто `All` — реальне гео бери з сегмента назви `[-4]`.
