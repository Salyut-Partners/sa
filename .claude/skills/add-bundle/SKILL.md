# Записати зв'язку в базу

Байер щойно відкрутив зв'язку й хоче зафіксувати результат. Твоя задача — зібрати
дані, скласти нотатку за схемою бази й відкрити PR. Байер git не бачить: усю роботу з
гілками, форком і PR робиш ти.

Терміни — у `CONTEXT.md`. Схема полів і словники — у `CLAUDE.md`.

## Крок 1. Тверді поля

Спитай одним коротким блоком, не по одному питанню:

- **вертикаль** — кредити · фінанси · оренда · jobs · dental · сезонка
- **гео** — код країни (`PL`, `DE`, `FR`…)
- **мова** — якою мовою крутили
- **джерело трафіку** — TikTok · Facebook · нативка
- **результат** — зайшла чи злила

Якщо байер уже щось із цього сказав у своєму повідомленні — не перепитуй, візьми звідти
й покажи, що взяв.

Значення поза словниками не вигадуй. Якщо вертикаль не підпадає під жодну — спитай
байера, до якої з наявних це ближче, і тільки якщо справді нікуди — запропонуй додати
нову й познач це в тексті PR, щоб куратор вирішив.

## Крок 2. Правило запису

**Зайшла** → записуємо завжди.

**Злила** → записуємо **тільки якщо байер знає причину**. Спитай прямо: «чому не пішло?»

- Причина є («різало на модерації через гео-копію», «бід вище $0.30 не тягне, економіка
  не сходиться») → записуємо.
- «Не знаю, просто не пішло» → **не записуємо**. Скажи байеру прямо: без причини запис
  нічого не навчить, база роздується, а користі нуль. Не наполягай і не вмовляй — просто
  поясни й закрий тему.

## Крок 3. Текст нотатки

Збери в прозі. Це не поля — не намагайся їх структурувати у front-matter:

- **підхід** — механіка оферу, що продавали і як
- **кути** — які персонажі/аудиторії пробували, який спрацював
- **ключі** — основні ключові слова
- **скрипт** — що звучало у відео (коротко або цілком, як дасть байер)
- **цифри** — спенд, дохід, ROI, період
- **висновок** — що спрацювало, або чому злила

Чого байер не сказав — не вигадуй. Пропусти рядок або постав «не вказано».

## Крок 4. Файл

Тека `bundles/`, ім'я kebab-case, унікальне по всій базі. Формат:
`<вертикаль>-<гео>-<коротка-суть>.md` — наприклад `orenda-pl-rent-to-own.md`.

Перевір `ls bundles/`, що такого імені ще нема.

```markdown
---
vertical: оренда
geo: PL
language: польська
traffic_source: TikTok
outcome: зайшла
source: запуск-<нік байера>
date: <сьогодні>
last_confirmed: <сьогодні>
---

# Оренда PL — rent-to-own, спрацювала бабуся

**Підхід.** Викуп житла замість оренди — стаття про те, як за платіж рівний оренді
вийти на власність.

**Кути.** Дівчина за будинком / бабуся / молода пара. Спрацювала бабуся, решта злили.

**Ключі.** tanie mieszkania do wynajęcia, mieszkanie na własność

**Скрипт.** …

**Цифри.** спенд $340, дохід $520, ROI ~53%, 9 днів

**Висновок.** …
```

Дату бери сьогоднішню. `last_confirmed` при створенні = `date`.

## Крок 5. Pull request

Репозиторій у байера read-only, тому пушимо у форк.

```bash
git checkout -b bundle/<slug>
git add bundles/<slug>.md
git commit -m "зв'язка: <вертикаль> <гео> — <результат>"
```

Форк — якщо його ще нема (`git remote -v` не показує ремоут байера):

```bash
gh repo fork --clone=false --remote=true
```

Далі пуш і PR:

```bash
git push -u <ремоут-форку> bundle/<slug>
gh pr create --fill --title "зв'язка: <вертикаль> <гео> — <результат>"
```

Поверни байеру посилання на PR і скажи, що куратор рев'юїть. Після цього переключи
гілку назад на `main`.

Якщо `gh` не авторизований — скажи байеру виконати `gh auth login` і зупинись. Не
намагайся обійти.

## Чого не робити

- Не комітити в `main` — тільки гілка + PR.
- Не редагувати чужі нотатки в цьому ж PR.
- Не ставити `status` на зв'язці — це поле лише для нотаток-знань.
- Не записувати злиту зв'язку без причини.
