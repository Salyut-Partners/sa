# Обговорити матрицю й створити теки

Матриця — разовий генератор папок, не файл. Осі: термгрупа, стаття, пара
мова+гео, кабінет. Джерело трафіку не вісь — воно на кабінеті в `topic.yaml`.
Бід і бюджет — параметри за замовчуванням із перевизначенням на клітинку.

Бюджет читання: `playbook/rules.md` цілком (два тижні тисячі слів — один раз
на розмову), більше нічого. Волта немає; чого нема в плейбуку — так і скажи.
Кожне правило, яке називаєш байеру, супроводжуй його позначкою надійності
(«зі слів партнера», «гіпотеза»).

## Крок 0. Тека топіка

Спитай, чи топік уже є на платформі.

- Немає — `bin/sa new <key> --name "…" --vertical <ніша> --geo DE,IT`, потім
  байер вписує `site`, кабінети (`accounts.<alias>: {source, ad_account,
  pixel}`) у `topic.yaml`.
- Є, створений руками — `bin/sa adopt <topic-id> --key <key> --vertical <ніша>`:
  ключі, статті й кабінети підхопляться самі. Ключ теки задає байер.

Команди виконуються з `~/sa/creative-factory-search`. Теки й yaml руками не
створюй — тільки командами; руками пишуться лише ключі, статті й скрипти.

## Крок 1. Інтейк по плейбуку

Одним блоком, не по одному питанню:

- **топік і кут** — під який дорогий ключ веде формулювання і хто там платить
  (розділ (a): ланцюг байт → ключ → видача → рекламодавець);
- **гео й мови** — пари `мова+країна`; тіри не змішувати, соло-гео на
  непрогрітому домені не пропонувати (розділи (e), (f));
- **термгрупи** — 1–3 групи ключів під різні статті: вузький / широкий / B2B
  (розділ (a) про 2–3 статті на зв'язку);
- **статті** — по одній на групу ключів, 550–700 слів, заголовок без гео
  (CMP-026);
- **кабінети** — alias із `topic.yaml`; різні вертикалі в один кабінет не
  заливати, 2–3 кампанії на зв'язку на кабінет (розділи (d), (e));
- **бід і бюджет** — від виплати по гео, тест 50% виплати, сітка бідів кроком
  у цент, тестовий бюджет $20–40 у Європі (розділ (b)).

Порахуй клітинки: термгрупи × статті × гео × кабінети. Понад ~10 кампаній на
підхід на гео — скажи, що це стеля з плейбука, і запропонуй розвести.

## Крок 2. JSON для `sa expand`

Рівно ці поля, інших `sa expand` не приймає:

```json
{
  "termgroups": { "tg-wh": { "keywords": ["warehouse jobs", "lager jobs"], "country": "All", "language": "All", "weight": null } },
  "articles":   { "a-wh": { "title": "Warehouse Jobs in Germany 2026" } },
  "geos":       [ { "language": "de", "country": "DE" } ],
  "accounts":   [ "main-tk" ],
  "defaults":   { "theme": "768", "rsoc_count": 5, "keyword_rotation": false, "headline": "Mehr erfahren",
                  "tsp": { "budget": 20, "bid": 0.45 } },
  "overrides":  [ { "where": { "country": "DE", "account": "main-tk" }, "set": { "tsp": { "bid": 0.47 } } } ]
}
```

- `termgroups`/`articles`: назви тек малими літерами; `null` замість об'єкта —
  тека вже є. `accounts` можна опустити — візьме всі кабінети топіка.
- `where` матчить осі `termgroup`, `article`, `language`, `country`, `account`;
  `set` бере `theme`, `rsoc_count`, `keyword_rotation`, `headline`, `tsp`, `name`.
- Імена кампаній складає `sa`: `<language>-<country>-<account>-<termgroup>-<article>`;
  `name` у `set` перевизначає. Байер імен не вигадує.

Покажи JSON байеру, дочекайся «так».

## Крок 3. Виклик і звіт

```sh
cd ~/sa/creative-factory-search && echo '<json>' | bin/sa expand <key>
```

Відповідь — JSON з `created`, `skipped`, `notes`. Перекажи: створено N
кампаній, пропущено M (уже були), що ще треба вписати руками — ключі в
`termgroups/<tg>/keywords.txt`, статті в `articles/<a>/article.md`, скрипти в
`campaigns/<c>/script.md`. Повторний виклик із тим самим JSON нічого не
створює — це нормально.

Одну кампанію пізніше додає `bin/sa new campaign <key> --termgroup … --article …
--language … --country … --account …`.

## Чого не робити

- Не запускати `sa apply` — ніколи, за жодних умов. Гейт `plan`/`--confirm` —
  межа безпеки; заборонено і в налаштуваннях репозиторію.
- Не писати `campaign.yaml`, `topic.yaml`, `state.json` руками.
- Не вигадувати команд, яких немає в `bin/sa --help`.
- Не шукати `sa-knowledge/` — його в цьому репозиторії немає.
