# Аналіз заливу

Зв'язка вже залита — тут не теоретизують, а дивляться цифри конкретного
запуску. Твоя задача — поставити діагноз, як партнер на менторському
розборі, і сказати, що робити далі: найдешевший тест, вирок із часовим
вікном або напрям росту.

Якщо заливу ще не було і байер тільки обмірковує ідею — це `brainstorm`,
не сюди.

Терміни — `CONTEXT.md`. Правила пошуку й мови — `CLAUDE.md`, діють тут
повністю.

## Крок 1. Спершу цифри — і спершу його бачення

1. **Спитай, як байер сам бачить ситуацію** — його версію накладай на
   цифри, а не навпаки.
2. **Дістань зріз за датою конкретного запуску**, не «загалом»:
   - скільки кампаній із запуску відпрацювало (з 10);
   - спенд по кампаніях і по днях — іде чи не йде;
   - ревеню/ROI по днях, не кумулятивно;
   - сетап: домен (вік, чи вже платив), кабінет, бід-сітка чи один бід,
     чи заливався щодня без пропусків;
   - дата запуску, гео, мова, сорс.

**Звідки цифри.** Reporting API платформи Roots — ендпоінти, неймінг
кампаній і готові рецепти в `.claude/skills/analyze-launch/api.md`;
прочитай його перед першим викликом. Коротко: `/campaigns` — спенд/ROI по
кампаніях (по днях — циклом, один виклик на день), `/revenue` — ревеню по
годинах (і RPC, але він порожній на більшості кампаній); зв'язка
знаходиться по `topic_id`, залив — по даті MMDD у назві кампанії.
**Поля кліків — пастка:** `s_clicks`, `cpc`, `rps` з API не збігаються з
тим, що байер бачить у дашборді (розбіжність до 8 разів). Кліки називай
тільки реконструйовані — `round(spend / s_cpa)`, ціна кліка — `s_cpa`;
гроші (spend, revenue, ROI) бери прямо. Деталі в `api.md`.
**Токен організаційний — фільтруй по маркеру байера з
назви кампанії і не показуй йому чужі цифри.** Маркер спитай, якщо не
знаєш. API впав або файла з ключем нема — питай цифри в байера одним
блоком і чесно кажи, що рахуєш з його слів. Цифр не вигадуй ніколи.

Чого API не знає (питай байера): стан кабінета/бан, домен, креативи
всередині кампаній, причина паузи.

## Крок 2. Скрипти й варіації на руках

Спитай, які скрипти та хуки зараз у заливі і скільки варіацій — щоб
пройтися по них: що вигоріло, де та сама варіація пачкою, чи є куди
розносити на нові макети й персонажів.

## Логіка ментора — діагностика

1. **Головна лінза — відсоток успішних кампаній із запуску.** 1–2 з 10 →
   зв'язка ще не робоча: при скейлі відсоток консервується, і жодна «ручка» —
   бюджет, перезалив, бід — слабку теорію не лікує
   (`knowledge/success-rate-before-scale.md`, `knowledge/majority-rule.md`).
2. **Діагноз — розвилкою за спендом.** *Спенд не йде* → перед вироком
   креативу виключи дешевші гіпотези по черзі: бан акаунта → чи заливався
   щодня → бід-сітка (однаковий бід на всіх кампаніях = «поставив їх в один
   аукціон») → і лише тоді креатив: глянець → вигорання → канібалізація.
   «Поганий акаунт» — остання гіпотеза, не перша
   (`knowledge/bid-grid-and-microspend.md`, `knowledge/grounded-creative-ranking.md`,
   `knowledge/creative-cannibalization.md`). *Спенд іде, а ROI слабкий* →
   питання не в креативі: трафік є, міняй статтю (2–3 інших) і напрям ключів,
   дивись виплату (`knowledge/multiple-articles-per-bundle.md`,
   `knowledge/term-groups-keys.md`).
3. **Перш ніж винити себе — виплата, домен, календар.** Просадка одного дня =
   найперше дроп виплати; просіло по всіх доменах одразу = провайдер, не ти;
   кінець місяця й серпень — системні дропи; непрогрітий домен «не платить»
   незалежно від ідеї, а важкий старт на новому кабінеті/домені — норма для
   всіх (`knowledge/one-day-drops.md`, `knowledge/payout-seasonality.md`,
   `knowledge/domain-trust-timeline.md`).
4. **Кожному вироку — своє часове вікно.** Кампанія розкручується 2–4 дні,
   мінус «по долару» на старті — норма; статті й виплаті вирок не раніше
   тижня проливу; домен гріється до двох місяців — після прогріву старі
   «непрацюючі» зв'язки перезапускають (`knowledge/domain-warmup-payout.md`,
   `knowledge/new-domain-warmup.md`).
5. **Планка тримається щоденним обсягом, зацеп — рандом:** його видавлюють
   кількістю й варіативністю, а не поліруванням переможця. Повторити
   переможця неможливо — заливають ті самі підходи в нових варіаціях
   (`knowledge/volume-conveyor.md`, `knowledge/daily-refresh.md`,
   `knowledge/copy-exact-fails.md`).
6. **Чорні скриньки не розгадують — перебирають.** Аукціон, піксель, акаунт,
   підстановка ключів Google — змінні, які не пояснити. Замість теорії —
   найдешевший тест, що розділяє гіпотези: 2–3 групи ключів × 2–3 статті,
   лишаєш що платить. Яка група ключів платить — апріорі невідомо ніколи;
   полірувати до ідеалу дорожче, ніж зробити нову статтю
   (`knowledge/bundle-variables.md`, `knowledge/google-keyword-substitution.md`,
   `knowledge/term-groups-keys.md`).
7. **«Куди рости» починається з питання «який обсяг очікуєш?»** Одне гео +
   одна мова + один підхід має стелю. Одиниця росту — не бюджет: новий
   підхід, суміжна зв'язка (будинки → квартири → авто), мовний пул гео
   (Бельгія → Франція → Швейцарія), другий сорс (зачепилось на TikTok →
   дублюй на Facebook). Соло-гео завжди плаває — стабільність дає тільки пул
   (`knowledge/scale-math.md`, `knowledge/adjacent-bundles.md`,
   `knowledge/targeting-geo-language.md`, `knowledge/facebook-second-channel.md`).

Нотатки з пунктів читай лише коли відповідний пункт спрацював і треба
пояснити глибше. Бюджет — **до 5 прочитаних нотаток**.

## Патерни — підсвічуй сам, як ментор

Якщо в цифрах чи словах байера видно знайомий патерн — назви його, навіть
якщо питали не про це: кампанії стопаються на $1–2 → креатив не ранжується;
«пожила день і померла» → спершу виплата дня; та сама варіація пачкою (тим
паче на кілька РК одразу) → канібалізація; «підніму бюджет — поїде» при 1–2
з 10 → рано; пропуски днів → сиплеться планка; новий домен «не платить» →
важкий старт — норма для всіх; «кинув гео, бо не йшли креативи», хоча воно
плюсувало → зарано, спершу 2–3 статті іншими кутами й іншими групами
ключів; «звузив мову таргетингу» → відрізав мігрантів, національну мову гео
ллють на всі мови; «кабінет не тягне те, що в інших їде» → кабінетна
лотерея, живих кабінетів 3–4 з 10 — не провина байера.

## Крок 3. Видача

Стисло — одна-дві теорії за раз, решта «на папірець»:

- **Діагноз** одним абзацом: що кажуть цифри і яка гіпотеза найдешевша до
  перевірки.
- **Наступний крок:** найдешевший тест, що розділяє гіпотези, або вирок із
  часовим вікном («рано, дай ще 2 дні розкрутки»), або — якщо питання «куди
  рости» — одиниця росту: новий підхід, суміжна зв'язка, мовний пул, другий
  сорс. Не бюджет.
- **По скриптах:** що з наявних варіацій вигоріло чи канібалізує, куди
  розносити далі.

Закінчи меню: «Далі можу: розписати перезалив чи структуру росту
(`launch-plan`), прогнати нові формулювання по комплаєнсу
(`compliance-check`), звірити з історією запусків (`check-history`)». Якщо
вирок фінальний — зайшла або злила зі зрозумілою причиною — нагадай
записати результат через `add-bundle`: причина зливу цінна не менше за успіх.

## Чого не робити

- Не діагнозувати без зрізу за датою запуску — «загалом» не діагноз.
- Не вигадувати цифр — API або слова байера, з чесною позначкою джерела.
- Не називати байеру `s_clicks`, `cpc`, `rps` з API — це інший знаменник
  кліка, ніж у його дашборді. Тільки `s_cpa` і `round(spend / s_cpa)`.
- Не радити підняти бюджет при 1–2 успішних з 10 — відсоток консервується.
- Не винити креатив, поки не виключені дешевші гіпотези (бан, пропуски
  днів, бід-сітка); «поганий акаунт» — остання гіпотеза.
- Не брейнштормити нову ідею з нуля — це `brainstorm`.
- Не писати в базу нічого.
