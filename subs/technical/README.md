# Автосубтитри для відео

Кидаєш відео в `inbox/` — забираєш готове зі вшитими субтитрами в `output/`.
Розпізнавання — mlx-whisper (large-v3-turbo) локально на Apple Silicon, вшивання — ffmpeg + libass.

## Запуск

```bash
cd ~/subs
./run.sh en
```

Або напряму:

```bash
cd ~/subs
./technical/.venv/bin/python technical/watch_folder.py --lang en
```

Термінал напише `Слідкую за /Users/…/subs/inbox` і залишиться висіти — так і має бути.
Не закривай його. Зупинити — `Ctrl+C`.

Далі перетягуєш відео в **підтеку** `~/subs/inbox/<стиль>/` — назва теки визначає вигляд
субтитрів. Через кілька секунд починається обробка. Результат —
`~/subs/output/2.<стиль>.mp4`, оригінал переїжджає в `~/subs/processed/`.

Відео, покладене просто в корінь `inbox/`, обробиться стилем за замовчуванням
(`yellow`; змінити — другим аргументом `./run.sh en red`).

## Із редактора

Таба «Субтитри» в `creative-factory-search` викликає цей самий скрипт
підпроцесом: `subtitle_styler.py <відео> -o <вихід> --style <стиль> [--lang <мова>]`.
Два службові прапорці для неї: `--list-styles` друкує словник `STYLES` як JSON
(працює й без venv), `--check` перевіряє оточення й друкує, чого бракує,
реченнями — саме їх показує панель. Стилі й далі живуть тільки тут.

Експорт креативів іде тим самим скриптом із третім прапорцем: `--words <файл>`
— готова розмітка слів (JSON-список `{text, start, end}`), яку редактор
збирає з таймкодів ElevenLabs. Тоді Whisper не запускається, слова на екрані —
буквально слова скрипта, і mlx на машині не потрібен; `--check` каже про це
окремим полем `burn_ok`. Решта шляху — нарізка на екрани, ASS, ffmpeg-full —
спільна з вотчером.

## Один файл без вотчера

```bash
cd ~/subs
./technical/.venv/bin/python technical/subtitle_styler.py ~/Desktop/video.mp4 --lang uk --style one-word
```

## Стилі

Усі стилі рендеряться КАПСОМ. У кожній підтеці `inbox/` лежить `_приклад.png` —
як цей стиль виглядає на кадрі.

| Тека / стиль | Вигляд |
|---|---|
| `yellow` | 4 слова на екран, активне жовтим — базовий |
| `green` | 3 слова, крупніше, активне салатовим (Hormozi-стиль) |
| `red` | те саме, що green, активне слово червоним |
| `box` | білий текст із обводкою, активне слово на чорній заокругленій плашці |
| `one-word` | по одному слову, найкрупніше |
| `simple` | статичні рядки по 7 слів, без підсвітки |

Субтитри стоять на 24% висоти від низу кадру — вище підпису, кнопок і нижньої
навігації TikTok. Змінити для всіх стилів разом — `TIKTOK_POS` у `technical/subtitle_styler.py`,
для окремого стилю — ключ `pos` у його блоці.

## Мова

`--lang en` / `uk` / `ru` / `pl` … Без прапорця — автовизначення (трохи повільніше й іноді помиляється на коротких роликах, тому краще вказувати явно).

## Встановлення на новий Mac

Потрібен Apple Silicon (M1+) — mlx працює лише на ньому.

```bash
# 1. Homebrew, якщо його ще немає
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. Системний Python від Apple не вміє створювати venv — потрібен свій
brew install python@3.11

# 3. Обидва ffmpeg, це не помилка (пояснення нижче)
brew install ffmpeg
brew install ffmpeg-full

# 4. Шрифт
brew install --cask font-montserrat

# 5. Оточення та бібліотеки
cd ~/subs/technical
/opt/homebrew/bin/python3.11 -m venv .venv
./.venv/bin/pip install mlx-whisper fonttools

# 6. Статичний жирний шрифт із варіативного
./.venv/bin/python make_font.py

# 7. Перший запуск — модель (~1.5 ГБ) качається один раз
cd ~/subs && ./run.sh
```

Шляхи скрізь припускають, що тека лежить у `~/subs`. Якщо вона деінде
(частий випадок — розпакували в `~/Downloads/subs`), підставляй свій шлях.

## Як зроблено плашку в стилі `box`

libass уміє малювати лише прямокутну заливку (`BorderStyle=3`), причому вона
замінює обводку — а потрібні одночасно біла обводка тексту й **заокруглена**
чорна плашка під активним словом. Тому плашка малюється графічним примітивом
(`\p1`) на нижньому шарі, а текст лягає поверх. Щоб знати, якої вона ширини,
скрипт сам міряє слова за таблицями шрифту (`FontMetrics`) і сам розставляє їх
через `\pos` — тобто розкладку рядка для цього стилю робить не libass, а ми.

Дві неочевидні речі, на яких це трималось:

- **libass бере за `Fontsize` не розмір em, а висоту рядка** за метриками
  `usWinAscent + usWinDescent`. Для Montserrat реальний em виходить 0.64 від
  заявленого кегля. Коефіцієнт рахується з самого файлу шрифту (`FontMetrics.scale`),
  тож для іншого шрифту перерахується автоматично.
- **Графічний примітив прив'язується до `\pos` не центром, а зі зсувом на
  половину свого bbox.** Тому шлях малюється від `(0,0)` до `(w,h)`, а не
  симетрично від центру — тоді з `\an5` він стає рівно в задану точку.

Параметри плашки — `radius_ratio`, `pad_x`, `pad_y` у блоці стилю; усі відносні
до кегля, тож вигляд однаковий на 720p і 1080p.

## Три граблі, на які тут наступають

1. **Потрібні обидва ffmpeg.** Звичайний `ffmpeg` з Homebrew зібраний БЕЗ
   libass — фільтра `ass` у ньому немає взагалі, вшити субтитри неможливо.
   А `ffmpeg-full` keg-only й не потрапляє в `PATH` — тому його не бачить
   mlx-whisper, який жорстко викликає `ffmpeg` з `PATH` для читання аудіо.
   Підсумок: один читає звук, другий малює субтитри. Скрипт сам знаходить
   потрібний бінарник для вшивання; перевизначити — змінна `FFMPEG`.

2. **Системний Python не створює venv.** `/usr/bin/python3` від Apple
   спотикається на `python3 -m venv`. Звідси `brew install python@3.11`.

3. **Montserrat із каску — варіативний шрифт із дефолтним інстансом Thin**,
   тому libass рендерив субтитри тонкими попри `Bold=1`. `make_font.py`
   запікає статичний ExtraBold (`wght=800`) у `fonts/MontserratSubs.ttf`
   з унікальною назвою сімʼї.
   Перегенерувати: `cd ~/subs/technical && ./.venv/bin/python make_font.py`.

## Кілька вотчерів одночасно

Це безпечно. Файл забирається з `inbox` атомарним `os.replace` у службову теку
`processed/.working/` — перейменувати одне й те саме джерело може лише один
процес, решта отримають `FileNotFoundError` і просто підуть далі. Два запущені
вотчери не б'ються за файли, а розбирають їх паралельно.

До цього другий вотчер падав із `Failed to load audio: No such file or directory` —
він устигав побачити файл, який перший уже переклав у `processed`.

Якщо обробка впала, файл повертається назад у свою підтеку `inbox`.

## Якщо правиш скрипти

Вотчер тримає модуль у памʼяті з моменту запуску — правки в `technical/subtitle_styler.py`
підхопляться лише після перезапуску (`Ctrl+C` і знову `./run.sh`).

## Налаштування вигляду

Кольори, розмір, КАПС, кількість слів на екран, позиція — словник `STYLES`
на початку `technical/subtitle_styler.py`. Кольори в ASS задаються як `&HBBGGRR`,
задом наперед відносно RGB: червоний `#FF3C3C` → `&H003C3CFF`.

## Свій шрифт

Кожен стиль може мати власний шрифт — ключ `font` із назвою сімʼї:

```python
"my-style": {
    ...
    "font": "Inter Subs",
}
```

Без цього ключа береться `DEFAULT_FONT`. Прапорець `--font` перекриває стилі
(для разових експериментів).

Порядок дій:

1. **Статичний шрифт** — просто поклади `.ttf` у `technical/fonts/`.
2. **Варіативний** — спочатку запечи потрібну вагу, інакше libass візьме
   дефолтний інстанс (у Montserrat це Thin):

   ```bash
   cd technical
   ./.venv/bin/python make_font.py --source ~/Library/Fonts/Inter\[wght\].ttf \
       --weight 700 --family "Inter Subs"
   ```

3. Вкажи назву сімʼї в ключі `font` стилю.

Назву сімʼї скрипт шукає в name-таблицях усіх файлів `fonts/` (`font_index()`).
Це важливо для стилів із заокругленою плашкою: ширина слів міряється саме
з файлу того шрифту, яким стиль малюється. Якщо файл не знайдено — буде
зрозуміла помилка зі списком доступних шрифтів, а не тихо зіпсований кадр.
